Advantages of Coding Agents

  • One advantage of coding agents is that they operate in a much more constrained environment than general language models.
  • The grammar of a programming language is often much simpler than that of a natural language — it is usually easier to parse or interpret.
  • APIs provide clearly defined boundaries.
  • Coding agents often perform well in constrained scenarios but can fail in production when capabilities must handle high cardinality. Michael Stonebraker pointed out that LLMs struggle with text-to-SQL in data warehouses because such schemas can have many tables and columns with similar or duplicated names.

Two Languages: Natural vs Programming

Suppose we have two languages:

  • A natural language with a million words and a complex grammar.
  • A typed programming language with ~100 words and a simple grammar (think Lisp). If we shorten identifiers in the code (e.g., variable and function names) to a compact, regular form we can keep even long programs within a small lexicon. (Recall that LLMs tokenize input into fixed tokens and represent them as numbers; this is about streamlining that process.)

Normalizing Code: Trade-offs

There are two main downsides to normalizing code:

  1. We lose grounding in natural language.
  2. We introduce ambiguity from many equivalent programs that differ only by identifier names.

The core issue is that many programs can be equivalent while using different variable and function names; a model must learn that these variants represent the same program, or it may incorrectly associate common names with particular behaviors.

Training Implications

Building an LLM with similar perplexity for both languages will require far fewer parameters for the second (programming) language. Consequently, it will need fewer tokens and less computation to train.

In practice we also want the programming model to understand queries and comments in natural language. As soon as we add natural language, however, we lose some of the benefits described above.

Combining Models: A Possible Approach

Can we combine the two models to get the best of both worlds? One idea is to use embeddings in the code to bridge representations between the compact, formal program space and natural language.

Conclusion

This note sketches trade-offs between compact program representations and natural language grounding; next steps include concrete experiments with normalization, embedding strategies, and hybrid model architectures.
